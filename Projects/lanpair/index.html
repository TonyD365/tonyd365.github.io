lanpair

Secure device pairing and messaging for the local network, in a few lines of Python.

Devices pair once. After that, every message is encrypted to its recipient, signed by its sender, and checked for replay before your code sees it.

cat why.txt

Why it exists

It came out of YTKTV Desk, where a front desk sends commands to the rooms. The usual approach on a LAN is an HTTP endpoint or UDP broadcast with no authentication, so anyone on the network can read traffic, send commands, or replay them. Doing it properly takes real security work, so I packaged that work into a library.

Quick look

pip install "lanpair[all]"
from lanpair import Host

with Host("Front desk") as host:
    if not host.devices:  # first run: show a QR code
        host.pairing_offer().print_qr()
        host.wait_for_pairing(timeout=300)
    for msg in host.messages():  # already verified
        print(msg.sender.name, msg.body)
        host.send(msg.sender.device_id, {"type": "ok"})

lanpair --threat-model

What it defends against

reading messages
Encrypted to the recipient with X25519 and ChaCha20-Poly1305.
fake commands
Every message is signed with Ed25519, and unpaired senders are dropped.
tampering
The signature and AEAD tag both fail.
redirecting
The recipient is signed in, and only it holds the decryption key.
replay
Sequence numbers are checked per peer and survive restarts.
stolen keys later
Forward secrecy from in-memory session keys that change every 10 minutes.
junk packets
Size limits and strict validation before any parsing work.

pytest --how

How it's tested

  • Linux, macOS, and Windows on Python 3.10 to 3.15
  • Fully typed with mypy strict
  • Property tests with Hypothesis and fuzzing with Atheris
  • Static analysis with CodeQL and workflow audits with zizmor
  • A simulated LAN with an attacker node that sniffs, replays, tampers, and forges
  • OpenSSF Best Practices passing badge

lanpair has not had an external security review yet, and 6-digit code pairing is still to come.
